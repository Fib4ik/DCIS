# Платформа доставки їжі (Food Delivery Platform)

Сучасна високопродуктивна розподілена платформа для замовлення та доставки їжі з ресторанів, яка об'єднує клієнтів, заклади харчування, кур'єрів та адміністраторів в єдину екосистему. Система спроєктована з урахуванням високих пікових навантажень (обідній та вечірній час), забезпечення мінімальної затримки при обробці замовлень та високої стійкості до збоїв завдяки мікросервісній архітектурі та асинхронній взаємодії.

Проєкт розроблено як навчально-промисловий еталонний макет, що супроводжується повноцінною технічною документацією від збору бізнес-вимог до забезпечення кібербезпеки та автоматизованого контролю якості (Fitness Functions).

## Зміст документації (Repository Index)

Нижче наведено посилання на всі частини системної документації, розгорнуті в репозиторії:

1. [Вимоги та стейкхолдери](docs/01-вимоги-та-стейкхолдери.md) — опис предметної області, стейкхолдери, матриця Влада-Інтерес, контекстна діаграма, User Stories та нефункціональні вимоги (NFR).
2. [Моделі систем](docs/02-моделі-систем.md) — Use-Case діаграма з відносинами `include`/`extend`, доменна модель (12+ сутностей) та діаграма компонентів із вхідними й вихідними інтерфейсами.
3. [Архітектура C4](docs/03-архітектура-c4.md) — порівняння архітектурних стилів (Моноліт, SOA, Microservices), обґрунтування вибору мікросервісів та діаграми C4 (Context, Container) із прив'язкою технологій.
4. [Поведінка та інтеграції](docs/04-поведінка-та-інтеграції.md) — діаграми послідовності, діяльності та станів, опис синхронних/асинхронних інтеграцій, приклад API-контракту, а також патерни Saga, Circuit Breaker і Retry.
5. [Журнал архітектурних рішень ADR](docs/05-журнал-adr.md) — 5 ключових записів архітектурних рішень (контекст, альтернативи, рішення, наслідки) щодо мікросервісів, баз даних, брокера повідомлень, саги та алгоритму доставки.
6. [Рефакторинг та патерни](docs/06-рефакторинг-патерни.md) — усунення анти-патерну "God Object" за допомогою патерну Strategy (розрахунок доставки) та поетапна міграція за патерном Strangler Fig.
7. [Безпека та якість](docs/07-безпека-та-якість.md) — моделювання загроз за методологією STRIDE, 3 архітектурні метрики (Fitness Functions) та їх автоматична перевірка у CI/CD пайплайні.

## Матриця відповідальності ролей (RACI / Напрями)

| Напрям / Роль | Основні завдання та відповідальність у проєкті |
| :--- | :--- |
| **Аналітик вимог** | • Збір бізнес-вимог та виявлення стейкхолдерів<br>• Формулювання User Stories та критеріїв прийняття (Gherkin style)<br>• Розробка доменної моделі та Use-Case сценаріїв |
| **Архітектор систем** | • Вибір мікросервісної архітектури та розробка C4-діаграм<br>• Проєктування поведінки (Saga, Sequence/Activity/State діаграми)<br>• Ведення журналу ADR та усунення анти-патернів (Strategy) |
| **Інженер якості та безпеки** | • Моделювання загроз безпеці за методом STRIDE<br>• Налаштування архітектурних метрик (Fitness Functions)<br>• Інтеграція перевірок якості та безпеки в CI/CD пайплайни |
